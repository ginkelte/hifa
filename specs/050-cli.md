# SPEC-050 — CLI

## 1. Responsibility and boundaries

**Does:** defines the complete command surface of `hifa` (Typer), context resolution
(`--db`, `.hifa.toml`, default team), the output contract (table / `--json` / `--quiet`),
the exit code table, and the mapping of domain errors to those exit codes. It is the entry
edge for humans and for scripts.

**Does NOT do (explicit):**
- It holds no business logic and no invariants: every command is *parse → call a use case →
  format*. Computing issue numbers, validating transitions or building SQL here is forbidden.
- It opens no SQLite connections and runs no SQL: it receives an already built `UnitOfWork` (`hifa.adapters.sqlite`).
- It does not print on its own (A6): every `stdout`/`stderr` write goes through `hifa/cli/output.py`.
- It brings up no network, sockets or HTTP, **except** `hifa serve` (A4, REQ-N004). No other command imports
  `fastapi`, `uvicorn` or `httpx`.
- It implements no authentication, telemetry, auto-update or remote sync.
- It defines neither the import/export formats (SPEC-080) nor the FTS search text (SPEC-090).

## 2. Public contract

### 2.1 Entrypoint and layout

```toml
# pyproject.toml
[project.scripts]
hifa = "hifa.cli.main:app"
```

```python
# src/hifa/cli/main.py
import typer

app = typer.Typer(
    name="hifa",
    no_args_is_help=True,
    add_completion=True,
    context_settings={"help_option_names": ["-h", "--help"]},
)

# registered sub-apps (one per file under cli/commands/)
app.add_typer(team_app, name="team")
app.add_typer(issue_app, name="issue")
app.add_typer(state_app, name="state")
app.add_typer(project_app, name="project")
app.add_typer(cycle_app, name="cycle")
app.add_typer(member_app, name="member")
app.add_typer(label_app, name="label")
app.add_typer(db_app, name="db")
```

```
src/hifa/cli/
├── main.py            # root app, global callback, sub-app registration
├── context.py         # CliContext: resolves db/team/member/color/format
├── output.py          # render_table, render_json, render_quiet, echo_err, color
├── errors.py          # domain error -> exit code + mensaje; handler global
├── refs.py            # parseo de refs: KEY-123, ULID, nombre de estado, prioridad
└── commands/
    ├── init.py  doctor.py  serve.py  search.py  transfer.py
    └── team.py  state.py  issue.py  project.py  cycle.py  member.py  label.py  db.py
```

`hifa.cli` may **only** import: `hifa.app.*`, `hifa.domain.*` (types and errors), `hifa.config`,
`hifa.adapters.sqlite.uow`, `typer`, `rich` **no** (forbidden: the table is drawn by hand in
`output.py`), stdlib. Importing `hifa.api.*` and `hifa.web.*` is forbidden; `hifa serve` imports
`uvicorn` **inside** the command function (deferred import) so that the rest of the CLI
works without the `[web]` extra (A5).

### 2.2 Global options and context resolution

Declared in the root callback. They must come **before** the subcommand:

| Option | Type | Default | Effect |
|---|---|---|---|
| `--db PATH` | path | see 2.2.1 | SQLite file to use |
| `--team TEXT` | str | see 2.2.2 | default team for this invocation |
| `--member TEXT` | str | see 2.2.3 | default member (`--mine`, `--assignee` with no argument) |
| `--json` | flag | off | JSON output (2.4.3) |
| `--quiet` / `-q` | flag | off | minimal output (2.4.4) |
| `--no-color` | flag | off | disables ANSI |
| `--no-input` | flag | off | never ask for confirmation: without a TTY, implicit `--yes`; with a TTY and confirmation required, exit 2 |
| `--version` | flag | — | prints `hifa <version>` and exits 0 |
| `-h/--help` | flag | — | help and exit 0 |

`--json` and `--quiet` together are contradictory: exit **2** with code `invalid_option`, without
writing anything to `stdout`.

`--db`, `--team` and `--member` are **also** accepted at leaf-command level (after the
subcommand); the leaf value wins over the global one. No other global option is duplicated.

#### 2.2.1 Database file resolution

The precedence table is the one in **SPEC-100 §2.2** (5 sources, `source` included: `flag`, `env`,
`file`, `xdg`, `home`) and is not repeated here. Edge rules:

1. `--db` (global or leaf) always wins; if it is empty it is ignored.
2. `HIFA_DB` wins over the file and over XDG.
3. `[workspace] db` in `.hifa.toml` is resolved **relative to the file's directory**; if the TOML
   does not declare `db`, the path is `<dir of .hifa.toml>/.hifa/hifa.db` (project-local, never XDG).
4. With no file in the tree: `$XDG_DATA_HOME/hifa/hifa.db` and, if the variable is unset, `source="home"`.

The file is resolved to an **absolute** path before opening it; the parent directory is created with
`0o700` if missing. If the file does not exist: read/write commands fail with exit **3**
and code `database_not_found` (they never create an empty database by accident); `hifa init` and
`hifa db migrate` do create it.

#### 2.2.2 Default team resolution

Order, first non-empty value wins. A value counts as **empty** if it is `""`, `null` or absent.

1. `--team` (global or leaf)
2. `HIFA_TEAM`
3. `[cli].default_team` in `.hifa.toml` (SPEC-100 §2.3; file default: `[team].key`)
4. If the workspace has **exactly one** non-archived team: that team
5. If it has 0 or ≥2: exit **2**, code `missing_context`, message
   `team required: use --team, HIFA_TEAM or [cli].default_team in .hifa.toml`

#### 2.2.3 Default member resolution

1. `--member`
2. `HIFA_MEMBER`
3. `NULL`

`.hifa.toml` does **not** declare a member (SPEC-100 §2.3): there is no `[defaults] member` and no
`[cli].default_member`. If the value matches no member (by `id`, `display_name` or `email`,
case-insensitive): exit **3** `not_found` with `field: "member"`. A member is never invented.

#### 2.2.4 `.hifa.toml` discovery

It is searched from `Path.cwd()` upwards to the filesystem root, at most 32 levels; the first one
found wins (SPEC-100 §2.4). The file format is **the one in SPEC-100 §2.3**, a single one:

```toml
[workspace]
name = "Ginkelte"
db = ".hifa/hifa.db"          # relativo al directorio del .hifa.toml
url_key = "ginkelte"

[team]
key = "ENG"
name = "Engineering"

[cli]
default_team = "ENG"

[web]
host = "127.0.0.1"
port = 7777
```

All keys are optional; an unknown section or key is ignored with a warning
(`unknown_key`), a value of the wrong type is exit 2 `invalid_config`. `hifa init` writes this
file according to SPEC-100 §4.2 R13 (only if it does not exist in the tree, or with `--force`).

and this table is fixed in the next bump (D-012).

Conventions:

- No command opens its own transaction or calls two write use cases: **one command =
  one use case = one `uow.write()`** (SPEC-040 R1). `issue label` with N labels is N commands

- `--sort`, `--reverse`, `--limit` and `--cursor` map onto the `ListFilters` fields and the keyset
  contract of **D-011** (see §4 R7/R8); the CLI does not define its own filter object.

### 2.4 Output contract

Rules that apply to **all** commands (A6):

- `stdout`: data only. `stderr`: diagnostics only (warnings, counts, errors, prompts).
- A command that mutates and succeeds writes the affected object to `stdout` (table or JSON depending
  on the format); never a message such as "OK".
- ANSI codes only if `stdout.isatty()` **and** `NO_COLOR` is not defined **and** `TERM != "dumb"`
  **and** `--no-color` was not passed. `--json` and `--quiet` imply no color.
- Table width: `min(terminal_width, 120)`; without a TTY: `120`. The `TITLE` column is the only
  one that is truncated (with `…`, U+2026, reserving 1 cell); the rest is never truncated.

#### 2.4.1 Table (default format)

UPPERCASE header, no borders or separators, two spaces between columns, numbers
right-aligned, text left-aligned. Priority is abbreviated to a single character:

| `priority` | 0 | 1 | 2 | 3 | 4 |
|---|---|---|---|---|---|
| glyph | `–` (U+2013) | `U` | `H` | `M` | `L` |

`issue list` table (exact columns, in this order):

```
IDENTIFIER  P  STATE        ASSIGNEE  TITLE                          LABELS        DUE

ENG-11      –  Backlog      –         Review nginx logs          –             –
```

Empty list: empty `stdout`; `stderr` receives `0 issues` (suppressed by `--quiet`). Exit 0.

#### 2.4.3 `--json`

A single JSON document per invocation, UTF-8, `indent=2`, `ensure_ascii=False`, with a trailing
newline.

**One list shape.** Every command that returns a collection emits an object whose only key is
`items`:

```json
{
  "items": [ /* objetos */ ]
}
```

`next_cursor`, `has_more` and `total_estimate` are **not** part of that shape. They exist only in
commands that paginate with `--cursor`, which in v1 is `issue list` alone (§2.5.3); that command
emits the same object plus the three cursor keys:

```json
{
  "items": [ /* objetos */ ],
  "next_cursor": "eyJ2Ij...dHki..." ,
  "has_more": true,
  "total_estimate": null
}
```

`next_cursor` is `null` when `has_more` is `false`. `total_estimate` is always `null` in v1
(the total is not counted: `COUNT(*)` over 10 000 rows would break REQ-N008) and exists only so that
the paginated envelope does not change shape in v2.

The base shape is the one `team list`, `project list`, `cycle list`, `member list`, `label list` and
`issue attach --list` print, and the one the implementation emits
(`output.emit(rows, json_obj={"items": rows})`): one record per element for `--quiet`, one row per
element for the table. Declaring the cursor keys on every list announced a pagination those
commands do not have (D-031).

`hifa search --json` returns the envelope defined in **SPEC-090 §2** (authority for the search
contract): `{hits: [{issue, snippet, score}], total, has_more, backend, took_ms}`. This document
does not redefine that envelope; if it changes, SPEC-090 changes and the reference here is adjusted.

#### 2.4.4 `--quiet`

One line per affected record, no header, no color, no diagnostics:

- read commands: the identifier (`ENG-123`) or `id` if the entity has no identifier;
- `issue create`: the `identifier` created;
- mutation commands: the affected `identifier`;
- `hifa db migrate`: nothing on `stdout`;
- commands with no record (e.g. `db vacuum`): nothing.

#### 2.4.5 Errors on `stderr`

Without `--json`: one line `hifa: <message>` and, if there is a `field`, ` (field: <field>)`.
With `--json`: the same envelope as the API (SPEC-060 §6.3) on `stderr`, and an empty `stdout`:

```json
{"error": {"code": "not_found", "message": "issue 'ENG-999' does not exist", "field": "ref"}}
```

The exit code never depends on the output format (A7).
### 2.5 Command tree (normative)

Conventions for this section: `REF` = `identifier` (`ENG-123`) or ULID; state and label `NAME`
is case-insensitive within the resolved team; `--yes` skips confirmation; every mutation accepts
`--json` and `--quiet`.

#### 2.5.1 Root, init, doctor, serve

| Command | Arguments / flags | `--json` | Exit |
|---|---|---|---|
| `hifa init` | `--name TEXT` (workspace, default `basename(cwd)`), `--team-key TEXT` (default `ENG`), `--team-name TEXT` (default `Engineering`), `--icon TEXT` (default `🚀`), `--color TEXT` (default `#5E6AD2`), `--timezone TEXT` (default `America/Santiago`), `--no-labels`, `--no-member`, `--force`, `--db PATH` (global) | `BootstrapResult` = `{created: str[], skipped: str[], workspace_id, team_id, member_id, db_path, already_initialized}` (**SPEC-100 §2.5**, the only shape) | 0,2,4 |
| `hifa doctor` | `--json`, `--verbose` | `DoctorReport` (**SPEC-100 §2.6**) | see **SPEC-100 §6** (documented exception: 0 ok, 1 warn, 2 fail, 3 not diagnosable) |
| `hifa serve` | `--host TEXT` (default `127.0.0.1`), `--port INT` (default `7777`), `--read-only`, `--open/--no-open` (default `--no-open`), `--reload` (dev only), `--json` (prints `{url, host, port, read_only}` before blocking) | see the column | 0,2,6 |
| `hifa search QUERY` | `--team`, `--state`, `--assignee`, `--label`, `--priority`, `--due`, `--is`, `--limit INT` (1-200, default 50), `--offset INT`, `--all`, `--count`, `--sort {relevance,updated,created,priority,due}` | envelope of **SPEC-090 §2.5** (`{hits,total,has_more,backend,took_ms}`) | 0,2 |

The `init` and `doctor` rows are a **literal copy** of SPEC-100 §2.7: same flags, same `--json`
envelope, same exit codes (D-013). `hifa search` declares no flags of its own: it adopts the row of
SPEC-090 §2.5 (D-016), including `--offset` and `--count`, which belong to the search contract and not
to the issue listing.

`hifa init` seeds, in a single transaction: 1 `workspace`, 1 `team`, **6** `workflow_state`, 4
workspace `labels` (`--no-labels` omits them) and 1 `member` + `team_membership` (`--no-member`
omits them), and writes `.hifa.toml` if it does not exist in the tree (SPEC-100 §3.1 and §4.2 R9-R13). It is
idempotent: on an already initialized database it exits 0 with `already_initialized: true`; with `--force`
it **does not** delete anything, it only re-seeds whatever is missing and rewrites `.hifa.toml` with a `.bak` copy.

Default states: those of **SPEC-100 §2.5** `DEFAULT_STATES` — `Triage`/`triage`/`#6B6F76`/1.0,
`Todo`/`unstarted`/`#E2E2E2`/2.0 (`is_default=1`), `Backlog`/`backlog`/`#6B6F76`/3.0,
`In Progress`/`started`/`#F2C94C`/4.0, `Done`/`completed`/`#5E6AD2`/5.0,
`Canceled`/`canceled`/`#95A2B3`/6.0 (D-034: `Todo` sits **before** `Backlog`). There is no `In Review`.
This list is not redefined here: if it changes, SPEC-100 changes and this spec references it.

#### 2.5.2 `team`

| Command | Arguments / flags | `--json` | Exit |
|---|---|---|---|
| `hifa team create KEY NAME` | `KEY` and `NAME` positional, both required; `--icon TEXT` (emoji), `--color TEXT` (`^#[0-9A-Fa-f]{6}$`), `--description TEXT`, `--timezone TEXT` (default `America/Santiago`), `--visibility {public,private,restricted}` | `Team` | 0,2,4 |
| `hifa team list` | `--all` (includes archived) | `{items: Team[]}`, each item + `issues_count` | 0 |
| `hifa team show [KEY]` | `KEY` optional (default: the resolved team of 2.2.2), **case-insensitive**; `--states` adds the workflow states | `Team` + `progress` + `states` (if `--states`) | 0,2,3 |

`create` is the **only** form that creates a team: there is no `team add` alias and no second
handler. (The previous revision of this table declared `team add --key --name`; it was never
implemented and is replaced here — D-030.) The command is *parse → delegate*, nothing else:

- `KEY` is validated by `create_team` through `identifier.validate_key` (SPEC-020 §2.2), **not** at
  this edge: the key is normalized first (`strip()` + `upper()`, so `ops` and `OPS` are the same
  team) and then matched against `KEY_PATTERN`. A key outside the pattern ⇒ exit 2,
  `Validation(rule="TEAM_KEY_INVALID")`. The CLI does not re-declare the pattern, so it has one
  owner.
- A `KEY` that already exists in the workspace ⇒ exit 4, `Conflict(rule="UNIQUE_TEAM_KEY")`
  (SPEC-040 §6: that is the only duplicate-team code, and the CLI invents no other).
- The call is `create_team(uow, CreateTeam(key=KEY, name=NAME, icon=…, color=…, description=…,
  timezone=…, visibility=…), actor)` (**SPEC-040 §2.2**, REQ-F040-14): **one** transaction that
  creates the workspace if it is missing, the team and its **6** default states. The CLI creates no
  state, invents no default and runs no SQL; the seeded states are those of SPEC-100 §2.5
  `DEFAULT_STATES`. Consequence, and the reason it is contract: a team either exists with a usable
  workflow or it does not exist at all — there is no half-created team to repair by hand.
- `CreateTeam` has no `parent`, `estimation_type` or `cycles_enabled` field today, so the command
  offers no flag for them. A flag the use case cannot carry is not declared at this edge (D-012).
- `list` orders by `key` **ASC** — not by name, not by `created_at` — and prints `KEY`, `NAME` and
  `ISSUES`, where `ISSUES` = `open_count + closed_count` of `v_team_progress` (SPEC-010 §3.3), that
  is every issue with `archived_at IS NULL AND trashed = 0`. A team with no issues has no row in the
  view: its count is `0`, not an error and not a blank. `--all` includes archived teams, flagged in
  the `ARCHIVED` column. `--json` emits `{items: Team[]}` in the same order, each item carrying
  `issues_count` as an **additive** field (default `0`, D-026).
- `show` accepts `KEY` in any case (`ops`, `Ops`, `OPS` normalize to the same team); an unknown key
  ⇒ exit 3, `NotFound(team)`. Without `KEY` it shows the team resolved by 2.2.2 and exits 2
  `missing_context` if that resolution fails.

`team show --json` adds `progress: {open_count, closed_count, urgent_open}` read from
`v_team_progress` (SPEC-010 §3.3) and `states: State[]` sorted by `position` ASC.
`team archive` is **not declared**: `archive_team` does not exist and is deferred with `update_team`
(D-031). The three revisions of this spec described it in mutually exclusive terms — open issues as
`Conflict`/exit 4 here, as `Validation(TEAM_HAS_OPEN_ISSUES)`/exit 2 in SPEC-040 §2.2/§6, and
re-archiving as idempotent/exit 0 in R5 — so the surfaces were removed instead of picking a winner
by accident. The row returns with the use case, in the revision that settles those semantics.

Normative notes:

- `create`: the title arrives positionally **or** through `--title`, never both (both ⇒ exit 2,
  `field: "title"`); neither ⇒ exit 2. `--description-file -` reads `stdin`.
- `create` without `--state` uses the team's workflow state with `is_default = 1`; if there is none,
  the one with the lowest `position`.
- `list --mine` = `assignee` = resolved member (2.2.3); no member ⇒ exit 2 `missing_context`.
- `--open` (default) ⇒ `is_open = 1`; `--all` ⇒ no `is_open` filter; `--archived` ⇒
  `archived_at IS NOT NULL`; `--trashed` ⇒ `trashed = 1` (implies `--all`). `--archived` and
  `--trashed` together ⇒ exit 2.
- `edit` with no flags at all ⇒ exit 2 `no_changes`. The `--clear-*` flags write `NULL`.
- `move --before REF` ⇒ `MoveIssue(position="before", before_id=REF, after_id=None)`; `--after REF` ⇒
  `MoveIssue(position="after", after_id=REF, before_id=None)` (SPEC-040 §2.1, `MoveIssue.before_id` /
  `after_id` are reference anchors). The
  `board_order` is computed by `move_issue` with `ranking.between` (SPEC-040 R8) and rebalances only if
  `between` raises `RANKING_EXHAUSTED` (SPEC-040 R9). The CLI **does not** send numeric positions. With
  `--before` and `--after` together ⇒ exit 2. With neither ⇒ `position="last"`.
- `delete` is *soft*: `trash_issue` sets `trashed = 1` and `updated_at`. **There is no physical delete**:
  there is no `--hard`, no cascade, no `DELETE FROM issue` (D-015; SPEC-030 R11). Compaction is
  `hifa db vacuum`, which deletes no logical rows. `--yes` avoids the prompt; without it, and with an
  interactive TTY, confirmation is requested (§4 R6).
- `relate` with `OTHER` == `REF` ⇒ exit 2; duplicate relation ⇒ exit 4.

writes `completed_at` = now; closing an already closed cycle is a no-op with exit 0. `cycle close`

ahead of time without `--force`; `--force` does not exist in v1 ⇒ the operation is rejected).

#### 2.5.6 `state`

| Command | Arguments / flags | `--json` | Exit |
|---|---|---|---|
| `hifa state list` | `--team KEY` (default: the team resolved by 2.2.2) | `{items: State[]}`, each item + `issues_count` | 0,2,3 |
| `hifa state create NAME` | `NAME` positional (required); `--type {triage,backlog,unstarted,started,completed,canceled}` (required), `--color HEX` (default `#6B6F76`), `--team KEY`, `--before NAME`, `--after NAME` | `State` | 0,2,3,4 |
| `hifa state update NAME` | `NAME` positional (required, case-insensitive); `--name NEW`, `--color HEX`, `--before NAME`, `--after NAME`, `--team KEY` | `State` | 0,2,3,4 |

The sub-app is registered in §2.1 and has **three** handlers, one per verb. It is numbered §2.5.6
and not §2.5.3 because §2.5.3–§2.5.5 are cited by section from SPEC-010, SPEC-060 and D-031; the
tree of §2.5 is ordered by family, not by menu order.

- This section publishes the surface of `create_state` / `update_state` / `list_states`
  (SPEC-040 §2.2). The CLI **validates nothing and touches no SQL**: it resolves names, builds the
  command object of §2.1, calls the use case and formats the result.
- **`list`** orders by `position` **ASC** — `workflow_state.position`, not name, not `created_at` —
  and prints `POSITION NAME TYPE COLOR DEFAULT ISSUES`. `POSITION` is rendered as the stored float
  (`1.0`, `2.0`, …); `DEFAULT` is `*` for the row with `is_default = 1` and `–` otherwise;
  `ISSUES` is the number of issues whose `state_id` is that state and that are visible
  (`archived_at IS NULL AND trashed = 0`), i.e. the same population as `v_team_progress`
  (SPEC-010 §3.3). A state with no issues prints `0`, never a blank. `--json` emits
  `{items: State[]}` in that same order, each item carrying `issues_count` as an **additive**
  field (default `0`, D-026); `State` is the canonical object of §2.4.2
  (`id, name, type, color, position, is_default`).
- **`NAME` is case-insensitive** within the resolved team (2.5 conventions, `refs.py`): `todo`,
  `Todo` and `TODO` name the same state. An unknown `NAME` (or `KEY`) ⇒ exit 3,
  `not_found`, and the message names the state the user typed.
- **Error codes come from SPEC-040 §6, not from here.** `--type` outside the six types ⇒ exit 2,
  `validation_error` with `error.field: "state_type"` (`Validation(STATE_TYPE_INVALID)`); a blank
  `NAME` ⇒ exit 2 (`Validation(STATE_NAME_EMPTY)`); a `--color` outside `^#[0-9A-Fa-f]{6}$` ⇒ exit 2
  (`Validation(COLOR_FORMAT)`); a name that already exists in the team, and a `--name NEW` that
  collides with a sibling, ⇒ exit 4, `conflict` (`Conflict(UNIQUE_STATE_NAME)`) — that is the
  duplicate code of §2.6 for states, and the CLI invents no other.
- **`--before NAME` / `--after NAME` are the human form of the reorder.** The user never types a
  float and never sees `position` in a flag: the CLI resolves the anchor (same team, same
  case-insensitive rule; an anchor that does not exist ⇒ exit 3), reads the team's states with
  `list_states`, computes the target `position` with `domain.ranking.between(prev, next)` — the
  same helper `move_issue` uses (SPEC-040 R8, R9) — and sends it in the command:
  `CreateState(position=…)` or `UpdateState(position=…)`. `--before A` means "immediately to the
  left of A" (`between(position_of_previous_state, position_of_A)`); `--after A` means
  "immediately to the right of A". With neither flag, `create` appends **after the last state**
  (`CreateState.position = None`, which SPEC-040 already defines as "last of the team") and
  `update` leaves `position` at `UNSET`. `--before` and `--after` together ⇒ exit 2
  `invalid_option`. Gap exhaustion on `workflow_state.position` is **not** rebalanced in v1
  (`rebalance_board` only touches `issue.board_order`): `RANKING_EXHAUSTED` ⇒ exit 2,
  `validation_error`, and the message names the two neighbors.
- **No other verb.** `hifa state` publishes `list`, `create` and `update` and nothing else: there is
  no `state archive`, no `state delete`, no `--archived`, no `--force` (D-035). Archiving or
  deleting a state needs a decision about the issues that live in it, and that decision is not
  taken; the surface does not promise it. `state update` therefore cannot empty a state either —
  moving issues is `hifa issue move` (SPEC-040 §2.2, `move_issue`).
- The **canonical order of a new team** is `DEFAULT_STATES` (SPEC-100 §2.5): `Triage`, `Todo`,
  `Backlog`, `In Progress`, `Done`, `Canceled` at `1.0…6.0` (D-034). A team initialized before
  D-034 keeps `Backlog` at `2.0` until its owner runs `hifa state update Backlog --after Todo` (or
  the equivalent drag on the board, SPEC-070 §2.6.5); **no migration renumbers `workflow_state`**.

### 2.6 Exit codes (normative)

Single map, identical to **D-014** (`specs/DECISIONS.md`). `doctor` is the **only** exception and
extends the map with `0/1/2/3` per SPEC-100 §6 (D-001).

| Code | Name | Cause | `error.code` |
|---|---|---|---|
| 0 | ok | success, including idempotent no-op | — |
| 1 | warn | **exclusive to `hifa doctor`**: there is a `warning` and no `critical` | — |
| 2 | validation | invalid input, incompatible flags, unresolvable context, invalid config | `validation_error`, `invalid_option`, `missing_context`, `invalid_config`, `no_changes`, `confirmation_required` |
| 3 | not found | nonexistent entity, database, file or label | `not_found`, `database_not_found` |
| 4 | conflict | uniqueness, references in use, duplicate, newer schema | `conflict` |
| 5 | invalid transition | illegal state change or cycle close (2.6.1) | `invalid_transition` |
| 6 | internal | unmapped exception, corrupt database, missing `[web]` extra | `internal_error`, `missing_web_extra`, `corrupt_database` |
| 130 | interrupted | `SIGINT` (Ctrl-C), POSIX convention, outside the domain mapping | `interrupted` |

No other command uses `1`: an internal bug is `6`. `hifa doctor` does not use `4/5/6` (SPEC-100 §6).

#### 2.6.1 Conditions of `invalid_transition` (exit 5)

They are evaluated in this order; the first one that applies wins:

1. target `state.type == "completed"` and the issue has ≥ 1 child (`issue.parent_id = issue.id`)
   whose `state.type` ∉ `{completed, canceled}`;
2. the target `state_id` belongs to a `workflow_state` with `archived_at IS NOT NULL`;
3. the issue is `trashed = 1` or `archived_at IS NOT NULL`;
4. `cycle close` on a cycle with a future `ends_at`.

A `state_id` from another team is **not** an invalid transition: it is `Validation` (exit 2), because
it breaks a composite FK of the schema (R4 of SPEC-010).

## 3. Data it touches

The CLI **writes no SQL and opens no connections**: it operates on entities through the use cases
of §2.3, which in turn use the `UnitOfWork` of SPEC-030. This table declares the observable effect
per command; the invariants are those of the SPEC-010 schema and are not re-validated here.

| Entity / table | Operation | Commands | Invariant backed by the schema |
|---|---|---|---|
| `workspace` | INSERT | `init` | 1 row per database; `url_key` UNIQUE |
| `team` | INSERT / UPDATE `archived_at` | `team create` (archiving is deferred, D-031) | `UNIQUE(workspace_id, key)` |
| `workflow_state` | INSERT (init) | `init` | `UNIQUE(team_id, name)` |
| `issue` | INSERT / UPDATE | `issue create\|edit\|move\|assign\|archive\|delete\|restore` | `UNIQUE(team_id, number)`, `UNIQUE(identifier)`, `CHECK(priority 0..4)` |
| `issue_label` | INSERT / DELETE | `issue label\|unlabel`, `label archive` | PK `(issue_id, label_id)` ⇒ idempotent operation |
| `issue_relation` | INSERT / DELETE | `issue relate [--undo]` | `UNIQUE(issue_id, related_issue_id, type)`, `CHECK(issue_id <> related_issue_id)` |
| `comment` | INSERT / SELECT | `issue comment` | `CHECK(length(trim(body)) > 0)` |
| `attachment` | INSERT / SELECT | `issue attach` | `url` NOT NULL; `metadata` is serialized JSON |
| `issue_history` | INSERT (implicit, by the use case) | every `issue` mutation | one row per changed field |
| `project` / `project_milestone` | INSERT / UPDATE | `project *` | `priority BETWEEN 0 AND 4` |
| `cycle` | INSERT / UPDATE `completed_at` | `cycle *` | `UNIQUE(team_id, number)`, `CHECK(ends_at > starts_at)` |
| `member` / `team_membership` | INSERT / UPDATE `is_active` | `member *` | `email` UNIQUE |
| `label` | INSERT / UPDATE `retired_at` | `label *` | `UNIQUE(workspace_id, team_id, name)` |
| `v_issue`, `v_priority`, `v_team_progress` | SELECT | `issue list\|show`, `team show`, `search` | read-only views (SPEC-010 §3.3) |
| `issue_fts` | SELECT | `search` | index maintained by triggers (SPEC-090) |

Nothing is ever written directly to `v_*` or to `issue_fts`.

## 4. Business rules

Every rule is verifiable by a test. The `REQ-*` are the auditable form of the same rule.

| ID | Rule |
|---|---|
| **R1** | **A6 — a single formatter.** No module under `cli/commands/` calls `print`, `typer.echo`, `sys.stdout.write` or builds ANSI. Everything goes through `cli/output.py`; a static test forbids those calls outside `output.py` and `errors.py`. → **REQ-F050-01** |
| **R2** | **One JSON shape per entity.** `--json` always emits the complete object of §2.4.2, with all its keys and in that order; no command adds or removes keys (the `--with` variants append at the end, never reorder). In table mode each command prints the fixed subset of columns declared in §2.5 and its examples in §2.7 — the table is a view, the JSON is the contract. → **REQ-F050-04** |
| **R3** | **Format resolved once.** `ctx.format ∈ {table, json, quiet}` is computed before running the use case; `--json` + `--quiet` ⇒ exit 2 before touching the database. → **REQ-F050-05** |
| **R4** | **Explicit context or error.** If the team cannot be resolved (2.2.2) the command fails with exit 2 `missing_context`; the "first team" is never chosen by alphabetical order or by `created_at`. → **REQ-F050-07** |
| **R5** | **Idempotency of the idempotent.** `init` on an initialized database, `label`/`relate` of something already present, `cycle close` of a closed cycle: exit 0 with no effects and no new row in `issue_history`. `team archive` is **not** an example of this rule: it is not declared (D-031) and its re-archive semantics are still open. → **REQ-F050-02** |
| **R6** | **Destructive requires confirmation.** `issue delete` (soft) without `--yes` and with an interactive TTY: prompt `Send ENG-13 to trash? [y/N]` on `stderr`; `N` or EOF ⇒ exit 2 `confirmation_required`, with no effect. `--no-input` without `--yes` ⇒ exit 2 straight away. There is no irreversible destructive operation in v1 (D-015). → **REQ-F050-10** |
| **R7** | **Keyset pagination, not offset.** `--cursor` is opaque (`base64url(sort_key + "\|" + id)`, D-011) and is forwarded without interpretation; the CLI never computes `OFFSET` and never accepts `--offset` outside `search` (where SPEC-090 sends it). `--limit` 1-200, default 50; `has_more` comes from requesting `limit + 1`. An invalid `--cursor` ⇒ exit 2 `validation_error` with `field: "cursor"`. → **REQ-F050-08** |
| **R8** | **Deterministic order.** `--sort ∈ {manual, created, updated, priority, due}` (default `manual`, D-011), each with its `sort_key` and `issue.id` as the final tiebreaker; `--reverse` flips the direction. Two runs over the same data return the same order. The `--sort` → `ListFilters` mapping is the one in SPEC-030 §2.6 and is not reordered at the edge. → **REQ-F050-08** |
| **R9** | **No network (A4).** `serve` is the only command that may open a socket. A test with `socket.socket` patched verifies that the remaining commands do not instantiate it. → **REQ-N050-03** |
| **R10** | **Deferred import of `[web]`.** `uvicorn`/`fastapi` are imported inside the body of `serve`; `import hifa.cli.main` does not load them. Without the extra, `serve` ⇒ exit 6 `missing_web_extra` with the instruction `pip install 'hifa[web]'`. → **REQ-F050-13** |
| **R11** | **`stderr` does not pollute `stdout`.** With `--json`, `stdout` contains exactly one parseable JSON document, even if there were warnings; a test runs `json.loads(stdout)` with `stderr` redirected to a buffer. → **REQ-F050-04** |
| **R12** | **`--quiet` is line-oriented.** One line per record, no header, no color, no counts; it works for `\| xargs`. → **REQ-F050-05** |
| **R13** | **Exit code independent of format.** The same error produces the same exit code with a table, `--json` or `--quiet` (A7). → **REQ-F050-06** |
| **R14** | **No secrets, no unresolved paths.** No command prints tokens or environment variables; paths are shown absolute and normalized. → **REQ-S050-03** |
| **R15** | **`attach` validates the URL scheme.** It accepts `http://`, `https://` and `file://` with an existing absolute path; it rejects `javascript:`, `data:`, relative paths and `..` that escape the allowed directory ⇒ exit 2 `field: "url"`. → **REQ-S050-04** |
| **R16** | **`serve` honors S001.** Default `127.0.0.1`; with `--host 0.0.0.0` (or any non-loopback address) it emits a warning on `stderr` **before** binding and requires the flag to be explicit; `--read-only` disables every write route of the HTTP edge. → **REQ-S050-02** |
| **R17** | **The tree of §2.5 is exhaustive and closed.** Every declared leaf command exists with exactly those flags; there are no undeclared commands or aliases (`hifa --help` and each `--help` are compared against §2.5 in a test). An undeclared flag ⇒ exit 2 (Typer behavior). → **REQ-F050-03** |
| **R18** | **Semantics of composite mutations.** `label`/`unlabel` accept N labels and run as N `AddLabel`/`RemoveLabel` commands (one transaction per label, SPEC-040 R1); there is no multi-label atomicity in v1 (GAP-05). `relate` creates a single direction (`blocked_by` is not persisted: `RelateIssues` inverts it); `assign --clear` and `--clear-assignee` write `NULL`, never `""`. → **REQ-F050-09** |
| **R19** | **`doctor` is diagnosis, not repair.** It reports `ok`/`info`/`warning`/`critical`/`skipped` per check; it exits **0** with no findings, **1** with some `warning` and no `critical`, **2** with some `critical`, **3** if the database does not exist or cannot be opened (SPEC-100 R19/D-001); it writes nothing to the database and applies no migrations. → **REQ-F050-11** |
| **R20** | **`export`/`import` are shells over SPEC-080.** The CLI resolves paths, format and `--on-conflict`; the column mapping and the row-by-row validation live in `hifa/app/transfer.py`. `import` opens **a single** `uow.write()` per run and `--dry-run` reverts it at the end (SPEC-080 R17, model (a)); the CLI handles no SAVEPOINTs. → **REQ-F050-12** |

## 5. Flow

### 5.1 Read command (`issue list`)

```
1. Typer parses argv and calls the root callback.
2. main callback: --json/--quiet/--no-color → ctx.format, ctx.color; --db/--team/--member → overrides.
3. context.resolve(): resolve_config (SPEC-100) → db path absoluto → team → member.
4. Abrir UoW (read-only si el comando no muta). Fallo: database_not_found → exit 3.
5. Construir ListFilters (SPEC-030 §2.6) desde los flags; validar combinaciones (--archived+--trashed, etc.).
6. Call app.list_issues(db, filters) and keep the keyset page (D-011).
7. output.render(ctx, items, cursor): tabla | json | quiet.
8. Cerrar UoW. exit 0.
```

### 5.2 Mutation command (`issue move`)

```
1..4 same as 5.1 (UoW in write mode: BEGIN IMMEDIATE inside the use case).
5. Resolver REF → issue (identifier exacto, luego ULID). No encontrado → exit 3.
6. Resolver --state a workflow_state del team del issue (nombre case-insensitive, luego ULID).
   Sin match → exit 3 field "state"; match ambiguo → exit 2.
7. app.move_issue(uow, MoveIssue(issue=REF, target_state=…, position=…, before_id=…, after_id=…), actor):
   valida 2.6.1 (puede lanzar InvalidTransition), calcula board_order con ranking.between
   (SPEC-040 R8) y rebalancea si hace falta (R9), escribe issue.updated_at,
   inserta issue_history(field="state_id").
8. COMMIT. Any exception → ROLLBACK and mapping in cli/errors.py.
9. output.render(ctx, issue) → exit 0.
```

### 5.3 Exception-to-exit-code mapping

```
try:
    result = use_case(...)
except Validation as e:      exit 2  (code=validation_error, field=e.field)
except NotFound as e:        exit 3  (code=not_found, field=e.field)
except Conflict as e:        exit 4  (code=conflict, field=e.field)
except InvalidTransition as e: exit 5 (code=invalid_transition, field=e.field)
except KeyboardInterrupt:    exit 130
except Exception as e:       exit 6  (code=internal_error; traza completa solo si HIFA_DEBUG=1)
```

The handler lives in `cli/errors.py` as a global `app = typer.Typer(...)` plus an
`@app.callback` that wraps the invocation; no command does `try/except` on domain errors.

## 6. Errors

| Domain error | When | Message (`stderr`, without `--json`) | `error.code` | Exit | HTTP (SPEC-060) |
|---|---|---|---|---|---|
| `Validation` | invalid flag, illegal combination, malformed date, state from another team | `hifa: <detail> (field: <field>)` | `validation_error` | 2 | 422 |
| `InvalidOption` | `--json` with `--quiet`, `--after` with `--before` | `hifa: --json and --quiet are mutually exclusive (field: output)` | `invalid_option` | 2 | 422 |
| `MissingContext` | unresolvable team/member | `hifa: team required: use --team, HIFA_TEAM or [cli].default_team in .hifa.toml` | `missing_context` | 2 | — |
| `InvalidConfig` | `.hifa.toml` with a wrong type or broken TOML | `hifa: invalid .hifa.toml: <detail> (field: <key>)` | `invalid_config` | 2 | — |
| `NoChanges` | `issue edit` with no flags | `hifa: nothing to change` | `no_changes` | 2 | — |
| `ConfirmationRequired` | destructive operation without `--yes` | `hifa: operation canceled` | `confirmation_required` | 2 | — |
| `NotFound` | nonexistent REF/team/member/label/project/cycle | `hifa: issue 'ENG-999' does not exist (field: ref)` | `not_found` | 3 | 404 |
| `DatabaseNotFound` | missing SQLite file | `hifa: database not found at <path>; run 'hifa init'` | `database_not_found` | 3 | 503 |
| `Conflict` | uniqueness, label in use, member with open issues, team with issues | `hifa: team with key 'ENG' already exists (field: key)` | `conflict` | 4 | 409 |
| `InvalidTransition` | 2.6.1 (1-4) | `hifa: cannot complete ENG-13: it has 2 open sub-issues` | `invalid_transition` | 5 | 409 |

| `CorruptDatabase` | `integrity_check` fails | `hifa: corrupt database: <detail>; see 'hifa doctor'` | `corrupt_database` | 6 | 500 |

| `KeyboardInterrupt` | Ctrl-C | (nothing) | `interrupted` | 130 | — |

Message catalog (the exact text is part of the contract because the tests assert it):
messages carry **no** trailing period, start in lowercase, quote the identifier with single
quotes, and append `(field: <field>)` only when there is a field.

## 9. Provenance

- Command and flag vocabulary: pattern from `gh`, `jj`, `bd` and `linear-cli`; the
  `resource verb` form (`hifa issue move`) follows the `git`/`gh` convention and avoids ambiguous
  positional flags.
- `identifier` as the primary argument (instead of ULID): author's decision, 2026-11-08 —
  the ULID is a storage detail, the identifier is what the human types.
- Exit codes 0/2/3/4/5/6: aligned with the domain error table of SPEC-000 A7 and with the
  `grep`/`diff` convention (2 = usage error), not with `sysexits.h`.
- `--json` with `indent=2` and the base envelope `{items}` (plus `next_cursor`/`has_more`/
  `total_estimate` only where the command paginates, D-031): the collection is always an object, never
  a bare array, so a script can swap CLI for HTTP without changing its parser.
- `total_estimate: null` instead of `total`: `COUNT(*)` over 10 000 rows violates REQ-N008; measured
  in the prototype (18 ms for `COUNT` vs 4 ms for the keyset page).
- `hifa label add|list|archive` was added (it was not in the original 050 brief): `issue label`
  requires existing labels and SPEC-060 exposes `/labels`; without it the command is not usable.
- `rich` prohibition: a 4-column table does not justify 12 ms of import or 8 MB of RSS,
  measured against the REQ-N050-02 budget.

## 10. Out of scope

- Installed shell completion (Typer generates it; its content is not tested).
- Interactive/TUI mode, embedded editor (`$EDITOR`), multi-step prompts.
- `hifa watch`, `hifa tui`, `hifa sync`.
- Message translation: the strings of §6 are in English and are not internationalized.
- Data format for import/export (SPEC-080) and search ranking (SPEC-090).
- Multi-workspace administration commands (`hifa workspace *`).
